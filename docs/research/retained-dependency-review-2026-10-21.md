## Database migration scope

Latest rusqlite is **0.40.2**, with bundled SQLite **3.53.2** and Rust MSRV **1.88**. The installed crate bundles SQLite 3.46.0. Relevant breaks across the intervening releases are stricter rejection of trailing/multiple SQL statements in `execute`/`prepare`, disabled unsigned conversions by default, optional statement-cache support, and ownership checks for closure hooks. The app uses multiple persistent stores, authorizer hooks, raw SQLite trace FFI, WAL recovery and a `progress_handler`; these are real acceptance surfaces. Audit numeric bindings and statement calls, and reopen existing history/state/task/chat fixtures, interrupted writes, compaction, cancellation, corruption classification and authorization denial. Read architecture persistence invariants before implementation. Nothing in the release notes alone establishes a need to rewrite database schemas or existing files. [Release history](https://github.com/rusqlite/rusqlite/releases), [current metadata](https://crates.io/api/v1/crates/rusqlite).

0.40.1 additionally fixes SQL injection through tainted SAVEPOINT names, and 0.40 fixes undefined behavior in `ToSqlOutput::from_rc`. Neither is evidence of a current exploit here: no application named-savepoint API use was found (there is a SQL-denial fixture). These are maintenance reasons to perform the upgrade with existing-file checks, not reasons to bypass them. New safe WAL hook/checkpoint bindings may be useful if that implementation is revisited, but do not change persistence coordination just to adopt them. [0.40.1 release](https://github.com/rusqlite/rusqlite/releases/tag/v0.40.1), [0.33 release](https://github.com/rusqlite/rusqlite/releases/tag/v0.33.0).

## Pins that remain justified

- **TypeScript 6.0.3:** stay until upstream tooling supports 7.0.2. Current svelte-check 4.7.7 declares TS `^5 || ^6`; current Kit 3.1.0 requires `^6`. TS 7 is therefore still an actual ecosystem blocker, unlike Vitest's migratable benchmark usage. Do not force an override simply for faster native compiler checks. [svelte-check metadata](https://registry.npmjs.org/svelte-check), [Kit metadata](https://registry.npmjs.org/@sveltejs%2fkit), [TS metadata](https://registry.npmjs.org/typescript).
- **Direct syn 2:** low priority. Latest syn is 3.0.9, but this direct dependency only parses architecture/lifecycle test source. Syn 3 reorganizes modifiers, receiver/safety/type/pattern shapes, removes span visits, and changes `Punctuated::pop`. Its new syntax coverage matters when our code adopts that syntax; the application runtime gains nothing merely from replacing the test parser. A focused migration should preserve visitor detection and negative fixtures. Keeping transitive syn 3 alongside direct syn 2 is supported version separation. [Syn 3 breaking changes](https://github.com/dtolnay/syn/releases/tag/3.0.0), [metadata](https://crates.io/api/v1/crates/syn).
- **Pi/Chord 1.3.0:** already current across all three direct packages; no newer upgrade exists. Preserve the returning-client OAuth/error-code patch until upstream incorporates it, with the source and built-helper loopback checks in the patch README. Their Node floor is 22.19.0, already reflected in package engines. [Pi AI metadata](https://registry.npmjs.org/@earendil-works%2fpi-ai), [Pi Durable metadata](https://registry.npmjs.org/@earendil-works%2fpi-durable), [Chord metadata](https://registry.npmjs.org/@earendil-works%2fchord).
- **Node types 24.19.2:** match Node 24 and the authentication helper's `node24` target. Latest types 26.6.5 would describe runtime APIs that Node 24 does not necessarily provide. Upgrade types with the runtime decision, not merely because the latest tag is 26. [Node types metadata](https://registry.npmjs.org/@types%2fnode).
- **corenn-kernels vendor 0.1.1:** still the latest published version. Replacing it with the registry package restores the unstable float feature gates we removed; there is no newer stable release to adopt. [Registry](https://crates.io/api/v1/crates/corenn-kernels), [published source](https://docs.rs/crate/corenn-kernels/0.1.1/source/src/lib.rs).
- **runed optional Kit peer warning:** latest 0.37.1 still declares Kit `^2.21.0`. Updating it does not establish Kit 3 support for its separate `runed/kit` helper. The previous analysis found that helper unused; retain that distinction rather than forcing a transitive major/minor override to hide the peer warning. [Registry metadata](https://registry.npmjs.org/runed).
