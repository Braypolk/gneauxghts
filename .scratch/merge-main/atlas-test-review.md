## Findings and bounded correction plan (recorded before source edits)

1. **P2 — The replacement double-click assertion can pass through the default note.** Main `e2e/specs/browser/map.spec.ts:13–17` selects Beta but double-clicks Alpha and expects Alpha. The backend starts with Alpha (`browserBackend.ts:533`). A broken pending-target handoff that still navigates to `/` can therefore show default Alpha and pass. The deleted map-navigation test selected Alpha and double-clicked nondefault Beta. Preserve that stronger direction and assert the prior selection before double-click. Use the cleanup reset helper to make the default workspace and viewport explicit, rather than depending on prior tests' persisted client state.

2. **P2 — The layout's containment oracle repeats the implementation predicate.** `atlasLayout.test.ts:17` checks `insideWithMargin(...)`, the same function `fitCloud` uses to decide whether enlargement is needed. An incorrect predicate can make both implementation and assertion pass. The fixture is an axis-aligned rectangle even after projection/scaling/translation, so compare node coordinates against its four numeric bounds with the required margin. Keep pairwise spacing and deterministic positions; no new geometry framework or test case is needed. The one array-identity assertion for metadata-only outline reuse is justified by the explicit cache contract and is not proposed for removal.

3. **P3 — Duplicate map fixture/interception ownership remains in the navigation-motion file.** Main `animation-navigation.spec.ts:65–96` constructs another complete two-note DTO and overrides raw invoke without restoring it; it also retains unused ResourceTiming setup from the removed Deck probe. Main already introduces `setAtlas` and event delivery for the map journeys. Move its meaningful hover/camera and region-Enter behavior to the map suite using that fixture boundary, deriving a single region from the existing typed notes. Remove the obsolete Deck-specific test and restore hook from the cleanup navigation file while retaining the real offscreen editor navigation regression. This reduces fixture/mocking machinery without deleting the region keyboard propagation regression. Do not create another generic backend or motion test framework.

4. **P3 — One new store case duplicates cleanup's stronger lifecycle owner.** Main `atlasStore.test.ts:422–431`, “does not attach subscriptions when initialization finishes after leaving the map,” is covered by cleanup's “joins initialization and never subscribes after disposal during visibility loading.” Keep the latter and its shared-promise/visibility/nonadoption assertions; carry the explicit no-loader assertion into that same lifecycle scenario if useful. Do not append both cases or restore main's second initialize counter. Cleanup's lifetime + joined initialization already owns the stronger transition.

## Distinct new protection to retain

- **ABA query race is not redundant.** Main's alpha→beta→alpha pending-result test detects an old result that would pass a current-query-string-only guard. Cleanup's existing old→new matrix alone does not establish this. Keep the case and use the existing injected search loader; avoid a separate raw-IPC mocking path for this owner test.
- **Deleted selection plus rejected refresh** retains state/error recovery. The browser checks the rendered reader and camera; the store rejection checks retaining the exact last accepted response and surfacing the failure. These are distinct boundaries. Keep it.
- **Search cases are different:** passive indexed body matches must not open the reader or move the camera; an explicit selection must survive a different and zero-result query. Neither is replaced by search-result DTO equality.
- **Source invalidation, touch/pinch, empty-space double-click, Enter/button navigation, redirect and region Enter** exercise distinct rendered handlers. Preserve them. The loaded-source invalidation case does not establish late-read rejection after a selection change; that remains a coverage limit rather than a rationale to delete the current case.
- **The 2,000-node browser case is not a duplicate of the 80 coincident-node unit case or the layout benchmark.** It tests mounted cardinality and working controls under load. Retain the one scale journey; no measured cost supports deleting it here. Its repeated zoom/fit commands are meaningful under the large DOM. It is not a latency benchmark: only the explicit completion bound and assertions are claimed.
- Layout's metadata/labels cache test and deleted/empty-map behavior retain actual contracts. The shared demo fixture is modest (38 notes) and reused by the read-only lab; do not introduce a second elaborate fixture factory merely to reduce these three small tests. Independent rectangle bounds fixes the weak oracle directly.
