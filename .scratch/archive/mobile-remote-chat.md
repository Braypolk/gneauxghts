# Mobile remote chat implementation

Implemented 2026-10-11. iOS supports the existing desktop OpenAI Responses and OpenAI-compatible HTTP providers. Compatible-server runtime admission and model discovery now permit iOS; Android retains its previous exclusion. Provider identities and persisted settings are unchanged. Construction stays inside AgentRuntime, with ChatService retaining durable runs, tools/evidence, context limits and proposal permissions.

Settings describe the remote server destination and physical-phone localhost behavior. The picker uses “Server”; iOS declares local-network usage. No chat inference runtime or weights were added. On-device semantic embeddings remain separate.

Both protocols pass the bounded actual-app [simulator validation](../mobile-ios-readiness/remote-chat-validation.md): discovery, streamed structured answers, history, note retrieval/citations, proposal Keep/Reject, cancellation/retry, 401/disconnect errors and interrupted-run retry. OpenAI used the user-selected local protocol fixture, not a live API. [Simulator Keychain persistence](../mobile-ios-readiness/keychain-validation.md) also passes with normal Xcode signing. [Native timeout/network and visual review checks](../mobile-ios-readiness/chat-network-review-validation.md) also exercise both 15-minute deadlines, socket failures/recovery, both create-review paths and the shared update editor. Review overlap, missing styling and touch sizing were corrected. Signed app replacement exposed [container relocation](mobile-ios-container-relocation.md), subsequently corrected and verified across legacy recovery and repeated signed simulator replacement. Physical/distribution credentials, physical lifecycle/network transitions, live-provider and physical proposal review acceptance remain in [issue 08](../mobile-ios-readiness/issues/08-ios-device-release-gate.md). This record closes implementation and simulator work; it does not declare iOS release readiness.
