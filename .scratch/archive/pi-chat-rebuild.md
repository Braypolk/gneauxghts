# Pi ordinary-chat rebuild

Recorded: 2026-10-16. **Complete: all ten tickets implemented and accepted within
the agreed desktop and iOS simulator scope.** This is a historical outcome,
outside the executable backlog. Physical-device testing is explicitly deferred.

The [approved scope](pi-chat-rebuild-scope.md) replaced ordinary chat for new
users with the shared Pi Durable/Pi AI/Chord 1.3.0 composition. The old application
chat runtime and opt-in evaluation composition were retired after desktop proof,
then affected checks and desktop journeys were repeated. Existing notes,
Note Timelines, authored files, settings and credentials were preserved; there is
no old-chat migration or fallback runtime.

## Implemented outcome

Ordinary chat streams Markdown and provider reasoning, presents actual tool and
compaction activity, retains human-visible history, supports conversation switching,
independent chats, queued follow-ups, withdrawal, Stop, persisted reopening and a
fresh New attempt after terminal failure. Initial titles require no inference.
Native search/read tools honor Full vault or Attached notes only and exclusions.
Admitted citations bind actual native read identities and distinguish retained
revisions from observed historical reads with navigation limits. Restriction ends
the old model context and starts a fresh conversation while retaining human history.

Pi owns generic history, submissions, tasks, scheduling, recovery, cancellation,
usage, progress and standard compaction. Gneauxghts retains presentation, native
SQLite/transport/credentials, vault authorization, read-source/citation admission
and canonical NoteTimeline publication. These responsibilities are defined by the
current [architecture](../../ARCHITECTURE.md#agent-runtime),
[behavior invariants](../../docs/architecture/behavior-invariants.md) and
[ADR 0012](../../docs/adr/0012-found-ordinary-chat-on-pi.md); this archive is
historical evidence, not another owner specification.

The product tool registry is read-only. A task-only write foundation proves real
native create/update through scoped authority, exact review or explicit direct
authorization, dirty-editor/conflict admission and publication reconciliation.
It does not ship model mutation tools, write settings or editable review UI.

text/reasoning, native reads/citations, software keyboard/touch/navigation,

and full native tests. Real synthetic create/update, exact review/direct authority,

with zero additional publication calls. A changed-body repeat preserves four prior

retains the aborted attempt, completes both turns and executes the queued user
once under the same valid authority. The isolated simulator app is left open at a
blank Full-vault chat on the actual local Qwen model; acceptance controllers and
fixture listeners are closed. No original vault was modified by these fixtures.

## Scope and evidence limits

Physical-device validation is explicitly deferred. Simulator results do not prove
device suspension/memory behavior, device signing, distribution or performance.
The local model ran at its configured network endpoint, not on the simulator.
No live hosted-provider, broad legacy feature parity, semantic citation entailment,
exact passage highlighting or normalized performance/resource-growth claim is made.
Bridge/storage observations are diagnostics, not permanent numerical budgets;
standard compaction reduces model context without promising deletion of immutable
history or WAL reclamation. Pi recovery alone does not guarantee exactly-once
external publication.

Exact Retry, managed transcripts/import, research/plans, implicit editor context,
non-note attachments, editable proposals, branching/archive UI and manual
compaction were outside the approved rebuild. The portable-overhead backlog was
superseded; its measurements and rejected designs remain historical.

Selected [sanitized evidence](pi-chat-rebuild-evidence/README.md) preserves desktop
and simulator conclusions, final checks and a selected changed-body recovery
receipt. Redundant working plans and repeated raw snapshots were pruned after
completion; committed originals remain in Git at `64cc3ff6`. Raw provider bodies, private controller credentials and live databases
are excluded. [Check receipt](pi-chat-rebuild-evidence/checks.json) records final
verification; individual outcomes retain failed-run causes and narrower limits.
