## Retain deliberately

- **Failed open recovery**: machine `returns selection to idle after a failed open` is retained. I found no equivalent rejected `getConversation` case in real-controller suites. Returning to the previous selection after failed open is useful behavior even though this existing test observes the aggregate directly. Root confirmed retention; do not delete the entire machine file to improve a file-count metric.
- **Architecture scanner**: keep ownership constraints and scanner probes. These guard forbidden second state owners, global History Mode placement, external-sync write authority and permission logic. Composed tests cannot prove absence of another writer. Two exact chat constructor/transition call-count assertions (`architectureFitness.test.ts`, around 118–119) are implementation pinning and can be deleted within the existing ownership case: the no-mirrored-fields check survives. This removes two assertions/~2 lines, no case. Do not rewrite the scanner or remove its executable-call probe because the external-sync rule still uses `calls`.
- **Controller initialization happy path** retained: settings, requested selection and readiness assertions have a distinct simple contract; deleting it merely because later tests initialize their fixture would overstate those later assertions.
- **Race/lifetime tests** retained across AppStore, Settings, Atlas and chat. Reversed responses, lifetime disposal/re-entry, joined acquisition with partial failure, local draft and selection supersession, first-send subscriber reentry, completion identity, same-message retry provenance, metadata vs request effects are different schedules/contracts.
- **AppStore versus Settings tests** are not duplicates: AppStore verifies independent domain admission and event application; Settings verifies local input/error/reporting state and slice result admission. In particular, delayed Settings view tests and staged path tests observe different state owners.
- **Privacy/security boundaries** retained: event sanitization and rendered sentinel suppression test different code; Markdown parser and rendered link/code/citation tests likewise protect different transformations. Preserve active-note identity, read-only revision/excerpt links, raw telemetry exclusion, HTML injection and no remote image loading.
- **Native adapters/contracts** retained: command names/nesting, receipt normalization, event payloads and Rust fixture comparison survive. Do not delete native adapters because fake controller tests use the same conceptual operation.
- **Settings rendering and recovery** retained: SSR readiness states, unsupported model, queued/working distinction, errors present only on model, complete history deletion warnings and retained error reporting have different branches. Root keeps mounted recovery/confirmation scenarios.
- **Common helpers** retained: navigation cancellation/save failure/external route change and history rehydration; keyboard normalization/conflict handling; selection anchors; highlighting/Unicode; text-size persistence, malformed storage and CSS/clamping; preference queue acknowledgement/recovery. Cheap branch tests are not excessive simply because they are small.
- **Task tests** retained: local calendar/DST and Rust date fixtures; dirty-document hash preparation and bounded retry; mismatched canonical identities; authored-write attribution; stale view/reorder/mutation response admission. These protect identity and persistence rather than duplicate UI forwarding.

## Bounded API forwarding follow-up (UI-R10)

Recommend four additional cases in `src/lib/features/chat/api.test.ts` for deletion (~65–70 lines, four cases):

- `uses the OpenAI-compatible local model discovery command`: `api.ts:432` returns `invoke` unchanged. Root-retained mounted browser `chat-controls.spec.ts`, `discovers and configures local model capabilities through mounted Settings controls`, discovers the configured endpoint's model and selects it. The local discovery result merge helper's offline/trim/ownership behavior remains separately covered. The unit's exact `baseUrl` argument assertion is lost as a dedicated assertion, while actual discovery invocation remains exercised.
- `persists capability selections for a specific local model`: `api.ts:438` forwards `{model, capabilities}` unchanged. The same mounted browser case already asserts the real command's model identity and four capability values, and visual toggle state. The duplicate unit freezes a second arbitrary model and capabilities literal.
- `checks key status for the requested provider`: `api.ts:357` returns the provider/configured result as-is. `stores and removes provider keys without requesting the key back` remains, as do mounted Settings credential/default preservation. Loss is explicit: the exact `getKeyStatus('local')` argument assertion has no identical retained assertion. This is a judgment that a one-to-one provider forwarding test adds less value than retained credential write/delete/privacy and real mounted selection coverage; do not claim full behavioral equivalence.
- `forwards compact activity events without exposing provider payloads`: `api.ts:592` forwards the payload as-is; the test injects no private/provider data and asserts only equality, so it does not establish its advertised privacy claim. Retain controller activity/cancellation behavior and `ChatMessage` rendered privacy sentinels, plus API completion/title transformation and terminal-before-receipt tests. Loss is the dedicated raw `chat://activity` branch equality assertion, not a sanitization guarantee.

Do not remove `loads unresolved proposals for a reopened conversation`: although a thin adapter, the durable proposal identity boundary has a useful native command pin alongside composed reopening tests. Keep complete permission identity, stable note exclusions, projection owner lookup, archive retention, normalization, rendered excerpt-to-wire adaptation, date conventions, settings compatibility defaults, and the new disjoint Settings/Atlas write regression. These contain policy/identity, transformation, recovery or reproduced bug contracts beyond call-copy trivia.

**Combined proposal: approximately 295–315 lines and 22 executed cases removed, plus two scanner assertions.** No new production/test code is proposed, apart from removing newly unused imports after deletion. This follow-up supersedes the earlier rough total, not its retained coverage decisions.
