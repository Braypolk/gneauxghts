## Explicit retention decisions

- Keep `services/retrieval::retrieval_scope_and_clear_invalidation_are_applied_at_delivery`. It owns the generic clear-during-read race; timeline agent may delete its fabricated task-list mirror, with this case as survivor.
- Keep all actual chat atomic admission/finalization fault tests, durable retry/branch identity, migration/recovery/proposal convergence, evidence source correctness and permissions/provider fault tests. Similar setup is not duplicate behavior.
- Keep both streamed runtime context-measurement integration and full request measurement wrapper test: one proves runtime hook/event wiring and content privacy; the other proves tools included and forwarded request unmodified. Keep capacity HTTP backoff test despite previous fixture fixes; it covers real metadata IO behavior.
- Keep `rig_hook_turns_share_the_streamed_completion_index`; this inexpensive boundary example protects external Rig one-based/product zero-based conversion, not arbitrary naming. No existing event assertion proves all its edge inputs.
- Keep prompt-policy tests this phase. Their literal prose assertions may be brittle, but deleting them without agreeing that model-instruction constraints are intentionally untested would silently drop distinct contracts. Tool permission tests do not prove prompt composition.
- Keep chunk ANN and note ANN load/delta/corrupt/unreferenced generation tests separately: adapters use distinct manifests/source inventories and recovery paths even though low-level graph storage is shared.
- Keep numerical retrieval/Atlas policy tests separately; near-zero centroid and scale-invariant retrieval policies intentionally differ.
- Keep scheduler update/delete/move/rebuild retry tests, batch fairness/newer-wins regressions, finite backoff, quiescence and building-marker cleanup. Similar pending maps encode different ordering cases.
- Keep asset sanitizer/MIME mapping/data-URL, safe subfolder, symlink and exclusive-write cases beyond the two proven overlaps. Keep lexical/chat-kind admission and cache-hit stale-delivery tests; lower-level scoring or gate tests do not substitute.
- Keep Atlas graph/layout/visibility/publication behavior, field-specific legacy defaults, label failure/cache/budget/progressive delivery tests. Do not remove performance bounds as mere constants when they bound actual workload.
- Keep architecture source parser support tests, command serde contracts, shared-fixture poison/unwind tests and ignored live/scale diagnostics. No new duplicate tests or helper framework proposed.
