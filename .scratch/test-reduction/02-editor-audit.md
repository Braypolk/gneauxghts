# Editor, images and proposals: deletion audit

Status: ready-for-agent
Progress: audit complete; awaiting root review before any source edits

Scope: frontend `notepad/editor`, `notepad/images`, `proposals`, and the actual proposal workspace composition in `notepad/orchestration/notepadProposalAdapter.test.ts`. Baseline is the current-tree snapshot in `../test-reduction/baseline.json`, not HEAD. No source has changed during this audit; no tests were run merely to count them.

## Recommendation

Delete **16 executable cases**, including two complete test files, and **five redundant fixtures inside an existing case**. The fixture removals are not counted as five tests. Estimated physical savings: **180–230 lines**, with no new tests, production changes, support abstractions, assertion relocation, skips, or scenario combinations. Exact physical and executable deltas will be measured against the saved snapshot after approval.

The proposal race tests grew because they found real data-loss defects. Most remain valuable. The proposed cuts remove happy paths now proved by the actual workspace/registry/editing/persistence composition, while retaining admission, identity, lifecycle, failed-save, and stale-commit distinctions.

Paths in the tables are relative to `src/lib/features/`. Line numbers identify the audit baseline and will shift after approved deletions.

## Unique contracts retained

- Shared editor runtime: all three batch transaction regressions (sequential, same-length, selection-interleaved); original state-start chaining; shared history with local scroll/selection; save identity; committed replacement history reset even for unchanged editor bytes; external/transient replacement notification semantics; reversed/clamped selection; runtime isolation. `undoSelection` and actual keyboard/drag block move regressions remain; their history annotations/caret assertions are not replaced by generic text outcomes.
- Presentation/lifecycle: readiness, first-frame latency, cancellation, focus-after-visible, disposed pane, native suspended-frame fallback, saved scroll vs caret, and awaited same-runtime restoration. Lifecycle mocks `settleEditorPresentation`, so its readiness tests do **not** subsume actual presentation helper tests. Frame fallback during presentation and during scroll settling are different operations.
- View-state persistence: round-trip ranges, legacy missing scroll, corrupt scroll normalization, negative scroll clamp, path-move identity fallback, cross-pane fallback and absent note remain. Pure serialization overlaps lifecycle partially, but identity/compatibility branches are independent and cheap.
- Formatting: full-marker vs inner unwrap, partial-range preservation, italic inside bold, link URL caret, reverse/multiline ranges, link no-op, real undo, surround-key admission and fenced-code exclusion remain. Surround-key tests exercise a separate input handler and cannot be replaced by toolbar command tests.
- Structural indentation: descendant subtrees, repeated depth, sibling groups, exclusive selection endpoint, mixed invalid groups, outdent subtree, task/mixed/ordered prefixes and prose fallback remain. Enter plain-line single-dispatch and list empty-item cases remain, including the independent empty-document handled result.
- Clipboard: pending copy with selection change, typing, owner retirement, disconnected view, rejected clipboard and normal undo remain. These are distinct guard inputs; collapsing them would weaken the reproduced stale-cut regression.
- Image parser: exact authored syntax preservation, source reset/reference forms, excluded code/comments/escape forms, all unsafe destinations, one-pass decoding and escaped label separators remain. Image commands retain stale/read-only/composition, multi-range admission, unchanged-size no-op and undo grouping. Upload retirement variants, partial retry, original-span mapping and duplicate execution remain. Cache lifetime/vault/fingerprint/eviction and viewer pan/fit rules remain.
- Proposals: passive no-focus/no-navigation, absent target, chat topology, retained-document reactivation/focus, no-pane callbacks/projection, metadata-only resolution without extra revision, widget callback identity, partial-hunk source span, supersession/failed admission cleanup, route opening retirement, route commit retirement, actual defensive flush/remount, failed terminal save, disk read failure, typing during reload, confirmed pending third click, conflict retry, mixed keep/undo and sibling teardown remain. The older mocked persistence flush test also asserts that a review does **not** bypass a real external conflict; the newer adapter teardown fixture does not assert that, so retain it.
- `reviewSession.test.ts` remains despite its size: it directly checks failed-open error visibility with empty presentation data. Removing it merely because it is a projection/getter test would lose a specific error-state assertion.

## Inspection ledger and limits

Read all test bodies in the five proposal test files, the proposal adapter composition, the seven image test files and all 20 editor test files. Compared the retained format command/parser/decorations composition directly. Read production paths needed to substantiate proposed cuts: `inlineFormatting.ts`, `structuralIndentation.ts`, `indentConfig.ts`, `imageState.ts`, `proposalOrchestration.ts`, `reviewSession.svelte.ts`, proposal reducer/root projection, editor root forwarding/state construction, lifecycle/presentation and view-state storage. Image parser/cache/upload test bodies were inspected for distinct scenarios; their production implementations were not re-audited exhaustively in this deletion pass, and no cuts depend on presumed equivalence there. Broader browser/native ownership is root's audit; no deletion here depends on an uninspected browser assertion.

No throughput claim is made from this static audit. Estimated line savings are modest because previous phases already replaced copied machinery with real composition fixtures. Large race tests are retained when their behavioral owner is unique. This proposal does not propose deleting production behavior to make tests dispensable.
