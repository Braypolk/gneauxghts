# Workspace, document, navigation, and History test reduction audit

Status: complete
Progress: Both audit tranches reviewed before edits. D01–D25 implemented; exact 34-case / 461-line result and focused verification recorded in `01-result.md`. No production edits or new tests.

## Decision criteria

Delete a test only when a retained executable owner exercises its production behavior, or its oracle merely tests a helper/literal rather than a production contract. This is actual deletion, not moving assertions into a table or changing the reported case count. Estimates exclude unrelated owners. No runtime-cost claims: the generated sequences previously measured cheaply and are assessed by their oracle, not enumeration count.

Paths below are relative to `src/lib/features/`; line references describe the current source and will move after deletion.

## Explicitly retain / do not infer duplication

- History omitted-selected-row regression: `historyModeMachine.test.ts` — `keeps a selected older revision pinned when a refresh page omits it`. Session refresh tests still include the selected row and are not substitutes. Also retain normal page-append dedup; citation bounded-context paging is a different contract.
- All History restore publication/adoption exclusivity, failed-entry recovery/reentry, obsolete-entry await checkpoints, and citation coordinates tests: separate admission stages/branches, not arbitrary parameter combinations. Restore and clear leave citation mode through different mutations.
- Persistence: queued task attribution, invalidation, newer local edits, saved identity, post-commit warnings/collisions, inactive-note restore pointer, preparation failure, readiness observation ordering and correlation. Readiness classifications share presentation code but represent distinct backend statuses and must not suppress authoritative writes. No candidate merely because this fixture is large.
- Editing service later **title plus body** preservation remains; persistence's later-edit test only changes body, so those two are not exact substitutes. Invalidated service capture returns null, versus persistence's dirty existing-baseline save, has a distinct direct-boundary assertion; retain pending further caller analysis.
- State operation token tests, external authoritative reconciliation while applying, stale conflict identities, tag-only edits/diagnostics, collision indexes and vault identity isolation.
- `paneOwnership` shared-handle dedup, shared Remember, and removal of pane state without removing documents remain. The apparent simple aliases include unique query/removal contracts.
- Pane failed-creation terminality and wrong-close-operation checks; real composition covers positive transitions but not all rejected machine events.
- Workspace store editor→chat→editor test: clearing conversation ID on return to editor is absent from the independent model. Keep content/conversation atomic updates and split-command reset too.
- Both generated production-state sequences remain. Do not delete based on unmeasured expense. Workspace has an independent expected-state model; document sequence also exercises conflict-status precedence across mixed operation/conflict states.
- Six `markdown/inlineFormatSpec.test.ts` command→parser→composed-decoration contracts stay. Editor owner is deleting redundant simple wrap/inner-unwrap checks in `editor/inlineFormatting.test.ts` against these owners.
- Markdown underscore syntax, triple/nested emphasis, escaped punctuation, selected-highlight fill versus caret, task widgets/undo, nested indentation, parser background update, and viewport-only rebuild guard have distinct grammar/behavior paths. No reduction justified solely by their small inputs.
- Search/Related matrices success/error, empty/dispose/reset/collapse and old-note/selection completion each invalidate through different event paths. Unicode examples cover three distinct coordinate hazards (non-BMP prefix, non-BMP match, excerpt truncation), not interchangeable copies.

## Declined larger opportunities (not blockers)

The following stay unchanged in this phase; no speculative deletion is required to finish the approved work:

- `locationMru.test.ts`: retain all cases except D24. Move-to-front checks list ordering while previous toggles check filtered retrieval; chat introduces a separate lastChat/retarget path. Per-pane isolation, path-or-ID removal, closed-pane transfer, missing-chat reinjection, legacy migration, and true cap are distinct. Production branches inspected.
- `searchReturnFocus` initial-empty guard and consumed-capture guard share a branch, but former prevents side effects before any capture and latter verifies clearing after success. Retain both: no exact higher-level owner currently asserts both no-capture and one-shot behavior. Do not merge them merely to reduce count.
- Command-bar duplicate empty Escape test has preventDefault assertion missing from the stronger restore-before-close case. Retain this small key-consumption contract rather than adding its assertion elsewhere to manufacture a deletion.
