## Removed mock-suite scenario mapping

The old `noteCommandController.test.ts` scenarios now cross real ownership boundaries in `notepadComposition.test.ts`: different-document parallel reads; coalesced same-document trailing read; save-failure blocks target load; two shared-document panes open independently; binding proceeds without rendered readiness; canonical proposal readback acknowledgment; changed canonical readback retains reviewed content as conflict; newly Remembered identity appears in MRU before New. The replacement adds independent lifetime/Forget/refresh-ordering cases rather than count-preserving mock assertions.

No broad controller fusion was warranted after the deep test seam removed caller setup duplication. WorkspacePane's capacity switch and ordinary switch still have distinct activation dependency names and target-selection policy; a generic helper would parameterize those differences for two short blocks without removing an owner or public concept. Registry/runtime, operation-specific adoption, pure history machine versus async session, and review workflow versus runtime session retain documented separate responsibilities. These are reviewed retained boundaries, not unfinished rewrite proposals.
