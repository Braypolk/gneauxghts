# Atlas fusion V3

Status: ready-for-human
Type: prototype

Question: Can the original spatial Atlas make notes readable at the point of exploration, while retaining fast connection browsing and an honest view of opening activity?

## User direction

The user finds the visualization tests interesting, but most require diverting attention to a distant preview and make note identity hard to read. Idea Weave supplies fast connection exploration; Topic × time supplies a useful sense of attention patterns. Build one V3 with the original Atlas at its heart. Keep the original and A–H available.

## Scope

The surviving preview uses the native Atlas cloud geography with deterministically spaced dots and plain filenames that fade together and scale linearly with zoom. Cloud names fit inside their original silhouettes. The map fills the available app surface. The shared bottom-centered SearchDock/SearchBar matches the original Atlas placement and keeps a Fit map action beside search. All comparison chrome, earlier A–H renderers, map filter controls and collection/export plumbing are removed.

Note and region information opens in a floating dismissible panel. Opening, browsing and closing the panel do not resize the map or change its camera. Selecting a note reveals its directly related names and connections; the panel browses connected notes, or search matches while a query is active. Full note source scrolls within the panel. A Regions button reopens the guide; clicking a cloud opens its region details. Region renames stay in memory. Activity remains available as note metadata, without a map encoding selector.

Opening activity is distinct from note centrality and semantic similarity. The existing app count has an eight-hour cooldown and decays one per 36 hours idle; it is a recent activity weight, not lifetime frequency. A read-only launcher payload exposes effective counts, with last-viewed timestamps separately. Missing activity is labelled no recorded views, not never read. Demo data and native-runtime fallback have timestamps only.

No production persistence, Atlas state ownership, or original Atlas behavior changes. All V3 interactions stay in memory.
