# Atlas fusion V3

Status: ready-for-human
Type: prototype

Question: Can the original spatial Atlas make notes readable at the point of exploration, while retaining fast connection browsing and an honest view of opening activity?

## User direction

The user finds the visualization tests interesting, but most require diverting attention to a distant preview and make note identity hard to read. Idea Weave supplies fast connection exploration; Topic × time supplies a useful sense of attention patterns. Build one V3 with the original Atlas at its heart. Keep the original and A–H available.

## Scope

Use native note relationships and cloud membership to seed one block layout. Hover identifies a note near its block; selecting a note puts a readable excerpt in a dedicated dock beside the map, or below it in a compact pane. The dock reserves space in overview too, so selecting, browsing or closing a note does not resize the map. Every note is a title block at every zoom level. Placement accounts for the complete block dimensions around native positions and is independent of viewport, zoom and selection. Blocks are packed within each original root topic, then whole topics are separated around their original centroids. Rounded topic hulls enclose the actual member block corners. Selection hides unrelated blocks without repacking. Blocks, titles, activity glyphs, hulls and connections share one world transform; connections attach directly to block boundaries. Stepping or scrolling through the browse pool keeps the reader in place while the graph highlights that note and its incident links. Full source expands inside the same dock. Search immediately identifies matching notes. Pan/zoom remain map operations. The overview dock provides example notes for each region and temporary region renames. Activity shapes are an optional lens, off by default.

Opening activity is distinct from note centrality and semantic similarity. The existing app count has an eight-hour cooldown and decays one per 36 hours idle; it is a recent activity weight, not lifetime frequency. A read-only launcher payload exposes effective counts, with last-viewed timestamps separately. Missing activity is labelled no recorded views, not never read. Demo data and native-runtime fallback have timestamps only.

No production persistence, Atlas state ownership, or original Atlas behavior changes. All V3 interactions stay in memory.
