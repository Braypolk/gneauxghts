## Higher-level fixtures checked for overlap

- `workspacePersistenceService.test.ts` keeps three different contracts: excluding review content while flushing ordinary documents, resaving edits made during the first save, and blocking unresolved external conflicts. Similar save setup does not make these substitutes for document runtime queue ownership.
- `paneEditorLifecycle.test.ts` distinguishes disposal before a queued mount starts, while `createEditor` is pending, during presentation measurement, and while a document bind owns the queue. Production has separate checks before enqueue work, after creation and after presentation; the immediate case expects no destroy, while the in-flight case expects one. These are actual different cleanup schedules.
- `historyModeSession.test.ts` retains finalization versus save failure, committed-clear display failure versus precommit failure, explicit health failures, selection/refresh ordering, publication/adoption exclusion, and stale citation checkpoints. The earlier audit's omitted-selection and ordinary-page dedup gaps are still present in the current session fixtures; no new owner appeared to justify deleting the low-level tests.
- Chat controller tests retain request-before-receipt, synchronous subscriber navigation, partial listener acquisition and post-disposal cleanup, same-message retry provenance, old terminal replay and permission ownership. The repeated fake API setup is shared already; deleting one schedule would remove its ordering guarantee, not a duplicate fixture layer.
