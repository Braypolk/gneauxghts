# Pi orchestration API assessment

Research date: 2026-10-17. Scope: installed `@earendil-works/pi-durable` / `pi-ai` 1.3.0; official upstream `main`; application runtime, edit, publication and conversation-view seams. Research only; no production changes or behavior tests.

Historical assessment: its three bounded adapter recommendations are now
[implemented and verified](../archive/pi-chat-adapter-cleanup.md). The native
publication, authority and citation boundaries remain in place. The source
locations below describe the pre-cleanup checkpoint and may have shifted.

## Conclusion

Pi already owns generation, tool tasks, replay policy, child-task ownership, queue placement, cancellation and conversation observation. The remaining custom `PublicationTask` is a domain task implemented **on** Pi, not a competing scheduler. Pi's public APIs do not currently provide an exact-payload approval or exactly-once external-effect primitive that can replace it. The clearest supported deletions are in selection initialization and redundant presentation work, rather than native publication proof.

## Tool lifecycle, approval and durable effects

The built-in `ToolTask` validates arguments, runs `beforeTool`, persists final arguments and replay policy before execution, then runs `afterTool` and commits the result. Safe recovery reruns only if both stored and current replay policy permit it. `beforeTool` can block or replace arguments; it does not expose a durable approval decision object or external-effect transaction. [Installed tool task](/Users/bray.polkinghorne/Documents/code/personal/Gneauxghts/node_modules/@earendil-works/pi-durable/dist/harness/tool.js:45), [installed hooks](/Users/bray.polkinghorne/Documents/code/personal/Gneauxghts/node_modules/@earendil-works/pi-durable/dist/harness/types.d.ts:712), [official implementation](https://raw.githubusercontent.com/earendil-works/pi/main/packages/durable/src/harness/tool.ts).

`api.executeTool(name, args, ctx, { key })` already deduplicates nested call admission across safe replay and stores a nested result. It is useful for tool-to-tool composition, but is explicitly not exactly-once execution. It cannot be substituted mechanically for `EditCallDoc` plus `PublicationTask`: generic tool abort writes an aborted/interrupted result, with no application abort callback to reconcile a committed effect, reject a prepared native intent and clear the exact review card. A hook that waits on a custom decision document would still need the custom durable state, exact-payload native approval and effect cleanup. [Installed nested API](/Users/bray.polkinghorne/Documents/code/personal/Gneauxghts/node_modules/@earendil-works/pi-durable/dist/harness/types.d.ts:203), [generic abort](/Users/bray.polkinghorne/Documents/code/personal/Gneauxghts/node_modules/@earendil-works/pi-durable/dist/harness/tool.js:121), [official tool lifecycle documentation](https://raw.githubusercontent.com/earendil-works/pi/main/packages/durable/README.md).

The existing atomic child creation has meaningful work: it writes the child ID and review card in the same commit. Replacing it with `api.createTask()` followed by `api.memo()` introduces a crash interval between task creation and remembering its identity. The candidate memo also prevents recomputing replacements against changed canonical content. [Atomic application continuation](/Users/bray.polkinghorne/Documents/code/personal/Gneauxghts/src/lib/features/chat/pi/edit.ts:33), [publication abort reconciliation](/Users/bray.polkinghorne/Documents/code/personal/Gneauxghts/src/lib/features/chat/pi/publication.ts:226).

Native `prepare/approve/publish/reconcile` must remain authoritative for exact payload hash approval, current source/base checks, document-owner admission and proven publication outcomes. The frontend document lease coordinates dirty/conflicted editors and adopts committed canonical content. Pi task checkpoints cannot atomically commit an external NoteTimeline effect together with its own task receipt. Lost acknowledgements therefore still require reconciliation before replay. [Native preparation/approval](/Users/bray.polkinghorne/Documents/code/personal/Gneauxghts/src-tauri/src/pi_chat/publication.rs:199), [native publication](/Users/bray.polkinghorne/Documents/code/personal/Gneauxghts/src-tauri/src/pi_chat/publication.rs:502), [document-owner bridge](/Users/bray.polkinghorne/Documents/code/personal/Gneauxghts/src/lib/features/chat/pi/publication.ts:131), [behavior invariant](/Users/bray.polkinghorne/Documents/code/personal/Gneauxghts/docs/architecture/behavior-invariants.md:962).

## Observation, list, history and submission boundaries

- `Conversation.watch()` is already a serialized exact-frame watch with bounded backlog; Pi owns attachment, cancellation and overflow. Keep the lightweight Svelte selection lifetime and UI state, but do not add another replay queue. `Conversation.viewState()` is an alternative Chord attachment, not a combined history/list controller. [Installed public surface](/Users/bray.polkinghorne/Documents/code/personal/Gneauxghts/node_modules/@earendil-works/pi-durable/dist/harness/types.d.ts:631).
- The mounted view contains only Agent, Live, Inbox, Provider and Usage documents. Custom `ChatDoc` and `EditReviewDoc` require their own watches or equivalent app projection. Removing those watches in favor of `view.docs` would lose updates. `watchDoc()` returns `undefined` when the document does not exist; it does not wait for a future creation. [Mounted kinds](/Users/bray.polkinghorne/Documents/code/personal/Gneauxghts/node_modules/@earendil-works/pi-durable/dist/harness/view.js:13), [missing-document handling](/Users/bray.polkinghorne/Documents/code/personal/Gneauxghts/node_modules/@earendil-works/pi-durable/dist/session/session.js:235).
- `ConversationView.entries` is the active transcript after the latest context head; full human-visible history is obtained with fork-aware `conversation.entries()` pages. Keep that pagination and merge. [Installed history API](/Users/bray.polkinghorne/Documents/code/personal/Gneauxghts/node_modules/@earendil-works/pi-durable/dist/harness/types.d.ts:620).
- No public conversation-list watch or app-metadata join exists in the examined installed exports or current upstream interfaces. `Storage.scanConversations()` and `subscribeCommits()` are lower-level building blocks; title/forgotten/model projection and page-versus-commit reconciliation still belong to the app. [Current list adapter](/Users/bray.polkinghorne/Documents/code/personal/Gneauxghts/src/lib/features/chat/ui/piConversationView.ts:137), [installed scan/query contracts](/Users/bray.polkinghorne/Documents/code/personal/Gneauxghts/node_modules/@earendil-works/pi-durable/dist/types.d.ts:575), [official public types](https://raw.githubusercontent.com/earendil-works/pi/main/packages/durable/src/types.ts).
- `submit`, busy follow-up queueing, submission deduplication by `requestId`, withdrawal and `abort` are Pi-owned already. The existing UI uses them. Pi has submission reacquisition/status/wait, but neither view nor event snapshot contains the latest terminal input; the initial submission scan remains justified for terminal failures without an assistant entry. A stable composer request ID could add admission-retry deduplication if that product behavior is desired; it is not a replacement for UI selection guards. [UI submission handling](/Users/bray.polkinghorne/Documents/code/personal/Gneauxghts/src/lib/features/chat/ui/piConversationView.ts:259), [installed submission API](/Users/bray.polkinghorne/Documents/code/personal/Gneauxghts/node_modules/@earendil-works/pi-durable/dist/harness/types.d.ts:50), [event snapshot shape](/Users/bray.polkinghorne/Documents/code/personal/Gneauxghts/node_modules/@earendil-works/pi-durable/dist/harness/events.d.ts:42).

## Startup, transport and upgrade-only possibilities

`Harness.open()` restores live task state without dispatching it. `resume()` enables scheduling; progress-requesting calls including submission, wait and abort enable it too. The app must therefore finish native binding/model installation before *any* such call, not merely before the final explicit `resume()`. Current startup installs mappings before the denied-conversation abort loop, then resumes. This is useful application composition rather than a second resume ledger. [Installed scheduler lifecycle](/Users/bray.polkinghorne/Documents/code/personal/Gneauxghts/node_modules/@earendil-works/pi-durable/dist/harness/scheduler.d.ts:76), [public auto-resume contract](/Users/bray.polkinghorne/Documents/code/personal/Gneauxghts/node_modules/@earendil-works/pi-durable/dist/harness/types.d.ts:640), [app startup](/Users/bray.polkinghorne/Documents/code/personal/Gneauxghts/src/lib/features/chat/pi/runtime.ts:136), [official harness source](https://raw.githubusercontent.com/earendil-works/pi/main/packages/durable/src/harness/harness.ts).

Pi AI already supplies `createProvider`, the provider catalog, parsers and custom `fetch`. The app uses those public seams. A browser/Tauri native HTTP and SQLite bridge is still required to retain Rust-owned credentials, endpoint selection, delivery admission and vault transaction lifetime; Node or Cloudflare adapters are not native Tauri replacements. [Installed provider factory](/Users/bray.polkinghorne/Documents/code/personal/Gneauxghts/node_modules/@earendil-works/pi-ai/dist/models.d.ts:211), [custom fetch](/Users/bray.polkinghorne/Documents/code/personal/Gneauxghts/node_modules/@earendil-works/pi-ai/dist/types.d.ts:53), [app provider bridge](/Users/bray.polkinghorne/Documents/code/personal/Gneauxghts/src/lib/features/chat/pi/nativeProvider.ts:23), [SQLite bridge](/Users/bray.polkinghorne/Documents/code/personal/Gneauxghts/src/lib/features/chat/pi/nativeSqlite.ts:22), [official model factory source](https://raw.githubusercontent.com/earendil-works/pi/main/packages/ai/src/models.ts).

Terminal citation admission must also stay in the provider wrapper: `GenerationHooks.afterResponse` returns `void`, rather than a replacement message, and task hook dispatch contains ordinary exceptions. Standard compaction calls model access directly, so a generation-only hook is not a uniform admission boundary. The current provider wrapper admits the terminal message before forwarding its successful `done` event to Pi. [Hook return contract](/Users/bray.polkinghorne/Documents/code/personal/Gneauxghts/node_modules/@earendil-works/pi-durable/dist/harness/types.d.ts:697), [hook exception contract](/Users/bray.polkinghorne/Documents/code/personal/Gneauxghts/node_modules/@earendil-works/pi-durable/dist/types.d.ts:122), [standard compaction model call](/Users/bray.polkinghorne/Documents/code/personal/Gneauxghts/node_modules/@earendil-works/pi-durable/dist/harness/compaction.js:128), [terminal admission implementation](/Users/bray.polkinghorne/Documents/code/personal/Gneauxghts/src/lib/features/chat/pi/nativeProvider.ts:149).

**Upgrade-only:** upstream callable model/settings suppliers permit swapping host configurations without reopening a harness. They do not by themselves replace the app's selected-model discovery, native authority validation, terminal citation admission or mutation of a model handle captured by an already-running request. No observed unreleased API removes those domain seams. Evaluate a released version before adopting; current `main` is not sufficient evidence of installed support. [Unreleased options](https://raw.githubusercontent.com/earendil-works/pi/main/packages/durable/src/harness/types.ts).

**Hypothesis, not upstream delegation:** a native lookup keyed by Pi's persisted provider session could potentially replace the frontend `bindings` map and all-history startup binding scan. It requires a new native lookup/admission contract and a separate way to ensure model metadata before resumed dispatch. There is no verified Pi API that supplies the application's authority tuple automatically, so this is an architectural redesign to assess independently, not a safe deletion justified by an upgrade.

## Recommended next boundary and verification

One bounded follow-up can move document initialization to the public creation hook,
derive initial model/metadata from the attached watches, and use view operations to
skip history work for progress-only frames. Keep root replacement/overflow handling,
full-history pagination and cancellation of partially attached selections. Verify
fresh creation, review arrival, title/forget changes during attachment, model display,
streaming, compaction and history paging through the existing adapter interface.
No publication, authority or citation redesign is proposed.
