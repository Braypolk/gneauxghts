## Findings corrected during review

1. **Missing workspace retirement fence.** The first frozen session invalidated superseded operations only by another same-pane operation. It had no lifetime disposal, so a delayed open/disk refresh after Notepad teardown could still adopt/bind. Issue01 requires stale operation and disposal safety. The owner added session.dispose, clears active admissions, rejects later refresh/ack work as appropriate, and calls it before view teardown. `notepadWorkspaceSession.test.ts` now drives a deferred open and deferred read, disposes the real session, and proves neither changes the original document or binds an editor. Accepted durable proposal settlement remains a distinct exact-document adoption, not stale navigation.
2. **Unused public release protocol.** After finishReviewDocument replaced the old callback, releaseUnreferencedDocument had no callers outside its declaration. Owner removed that export; the private helper remains. This was a small speculative-generality/middle-man judgment, not a hard naming rule violation.
3. **Route teardown could accidentally save an unaccepted review.** Independently corroborated audit_agent's finding: Notepad starts an asynchronous workspace flush, then the initial proposal disposal cleared review suppression before the flush resumed. Because NoteDraftState survives remount, delayed cleanup alone also exposed proposed bytes as ordinary dirty text later. The approved fix retains document root/workflow across route lifetime, retires local admission, binds the new route's callbacks, and lets already-admitted durable settlement complete through exact retained-document adoption. The real adapter composition regression starts the flush then disposes: B ordinary edits save, A proposed/outside-hunk bytes do not; a new route continues and resolves A without lost edits. A separate in-flight commit handoff test proves one durable call, preserved later edits, and eventual idle state.
