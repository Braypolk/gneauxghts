# Pi Durable: embedded desktop and iOS source investigation

Investigated: 2026-10-15. Research only; no production dependency or ownership changes.

## Finding

**Pi Durable is a credible cross-platform core candidate, including an in-process JavaScript route inside the existing webview. It should not be rejected because its package declares Node >=22.19.** Its portable core and SQLite engine are intentionally separated from Node adapters, and exact published packages passed an isolated browser bundle and restricted-runtime conversation smoke test. A real WKWebView + native SQLite/provider integration remains unverified.

It can replace much more session machinery than the current Rig loop: transcript/task persistence, durable input admission, model/tool execution checkpoints, replay classification, committed streaming state, branching, compaction, usage, and cancellation coordination. It supplies primitives for durable reviewed proposals, rather than a complete human approval product. Its **durable package is weeks old and explicitly experimental**, independently of Pi's established coding-agent adoption.

## Platform facts from source

The main Durable entry imports session, scheduler, harness, tools' runtime types, document, and memory-storage code. Node filesystem, process, image-worker, and SQLite bindings are exposed through separate entry points. Core scheduler uses promises, cancellation contexts, timers, and persisted task state. Browser timer objects without `unref()` are handled explicitly. [Public exports](https://github.com/earendil-works/pi/blob/4954d760504c11df9b2cbdc040346107b6a8153d/packages/durable/src/index.ts), [scheduler](https://github.com/earendil-works/pi/blob/4954d760504c11df9b2cbdc040346107b6a8153d/packages/durable/src/harness/scheduler.ts).

This is an intentional portable architecture: upstream has a **Durable browser smoke test** bundling core, portable JSONL, and portable SQLite, asserting that Node adapters are absent. Its import-graph budgets also prevent accidental heavyweight dependencies at narrow entry points. This establishes browser bundling intent, not an upstream iOS deployment guarantee. [Browser check](https://github.com/earendil-works/pi/blob/4954d760504c11df9b2cbdc040346107b6a8153d/scripts/check-browser-smoke.mjs), [entry graph checks](https://github.com/earendil-works/pi/blob/4954d760504c11df9b2cbdc040346107b6a8153d/scripts/check-entry-graphs.mjs).

`pi-ai`'s root is explicitly core-only, with providers selected separately. Environment/auth code guards absent Node facilities. A custom `Models` provider can bridge a native request implementation; alternatively selected browser-compatible providers can run in JS. Neither proves secure credential integration, local endpoint compatibility, CORS behavior, or cancellation on an iPhone. [AI root](https://github.com/earendil-works/pi/blob/4954d760504c11df9b2cbdc040346107b6a8153d/packages/ai/src/index.ts), [models/provider interface](https://github.com/earendil-works/pi/blob/4954d760504c11df9b2cbdc040346107b6a8153d/packages/ai/src/models.ts), [auth context](https://github.com/earendil-works/pi/blob/4954d760504c11df9b2cbdc040346107b6a8153d/packages/ai/src/auth/context.ts).

Chord root reaches its transport code, including optional guarded Node compression and Buffer-based object transport paths. Durable's local document state does not require those paths; browser-safe WebSocket alternatives exist. Do not claim every exported Chord transport works without Node. [Chord transport](https://github.com/earendil-works/pi/blob/4954d760504c11df9b2cbdc040346107b6a8153d/packages/chord/src/link.ts).

### Native storage bridge

The portable SQLite implementation accepts an asynchronous `SqliteDatabase` facade with `exec/run/get/all/transaction/close`. Its operations can execute outside the harness runtime. A Rust Tauri adapter is feasible without rewriting the durable scheduler or storage schema: host transaction handles must serialize unrelated operations, commit/rollback correctly, and settle only after storage outcome. Namespace prefixes allow host and Pi tables to coexist. [Facade contract](https://github.com/earendil-works/pi/blob/4954d760504c11df9b2cbdc040346107b6a8153d/packages/durable/src/storage/sqlite/database.ts), [storage engine](https://github.com/earendil-works/pi/blob/4954d760504c11df9b2cbdc040346107b6a8153d/packages/durable/src/storage/sqlite/storage.ts).

Thus the likely local design is: JS Pi harness owns conversation/task semantics; Rust provides SQLite transaction operations, secure provider access, and note tools; Svelte consumes Pi committed projections. Keeping a second canonical Rust `ChatService` session/task state machine would defeat the replacement. Storage failure is session-fatal except explicitly classified request failures; transient storage retries belong in the adapter. [Session error behavior](https://github.com/earendil-works/pi/blob/4954d760504c11df9b2cbdc040346107b6a8153d/packages/durable/src/session/session.ts).

Native iOS remains a separate acceptance gate: deploy a bundled JS runtime in WKWebView, verify required Web APIs such as `Promise.withResolvers`, Web Crypto, and cancellation, then test kill/reload, background/foreground, memory pressure, and interrupted IPC transactions. Persistence permits recovery after execution resumes; it does not imply continued execution while iOS suspends the webview. No upstream iOS acceptance evidence was found.

## Approval and proposal replacement boundary

`beforeTool` may asynchronously replace arguments or block a call, and hooks can keep first-writer durable task memos. This is not a ready `interrupt/resume-with-edited-input` API: returning `block` settles an error result, rather than parking an approval request. The host must define pending request state and the UI response protocol. [Hook interface](https://github.com/earendil-works/pi/blob/4954d760504c11df9b2cbdc040346107b6a8153d/packages/durable/src/harness/types.ts).

A registered review tool can instead keep a task-scoped JSON document, watch the human-edited decision, and resume after restart. Durable documents and task checkpoints supply storage and recovery; Gneauxghts supplies proposal identity, editable body/diff, rejection, current-note preconditions, and approval authorization. Arbitrary human/network effects must remain outside commit callbacks. [Task/document contracts](https://github.com/earendil-works/pi/blob/4954d760504c11df9b2cbdc040346107b6a8153d/packages/durable/src/types.ts), [document examples](https://github.com/earendil-works/pi/blob/4954d760504c11df9b2cbdc040346107b6a8153d/packages/durable/test/examples/11-extension-state.ts).

Tool intent is persisted before execution. Interrupted tools rerun only if both their stored and current policy say `replay: "safe"`; otherwise they become interrupted results. A supposedly safe tool can still execute twice if the native note write succeeds before Pi stores the tool outcome. **Pi does not supply exactly-once Markdown publication.** Keep NoteTimeline as write authority and supply native idempotency/receipt reconciliation keyed to the durable proposal/task and accepted payload. A memo written before an external effect is not proof the effect occurred. [Tool recovery implementation](https://github.com/earendil-works/pi/blob/4954d760504c11df9b2cbdc040346107b6a8153d/packages/durable/src/harness/tool.ts), [idempotent service recovery tests](https://github.com/earendil-works/pi/blob/4954d760504c11df9b2cbdc040346107b6a8153d/packages/durable/test/harness-tasks-recovery.test.ts).

Evidence permissions, current canonical bytes, immutable revision identities, citation issuance/freshness, and note-write concurrency remain domain policy. Pi's generation/compaction hooks can host that policy; its default transcript replay/summary is not sufficient to preserve Gneauxghts's rule that past assistant prose and stale excerpts never become fresh evidence. Retaining those domain checks is compatible with deleting generic session orchestration. [Generation hooks](https://github.com/earendil-works/pi/blob/4954d760504c11df9b2cbdc040346107b6a8153d/packages/durable/src/harness/generation.ts), [compaction](https://github.com/earendil-works/pi/blob/4954d760504c11df9b2cbdc040346107b6a8153d/packages/durable/src/harness/compaction.ts).

## Isolated experiments actually run

Temporary directory: `/tmp/gneauxghts-pi-browser-check`. Exact `pi-durable`, `pi-ai`, and `chord` 1.3.0 plus esbuild 0.25.12; `npm install --ignore-scripts --no-audit --no-fund`. No lifecycle scripts or repository code ran during install.

1. **Browser bundling:** core exports including portable SQLite/JSONL, fake provider, and TypeBox bundled as browser ESM, 988,643 bytes unminified, zero external imports. Adding selected OpenAI and Anthropic providers bundled to 2,597,772 bytes; the output retained one guarded `node:fs` require in a Bun environment fallback, without an eager Node import. These deliberately broad export bundles are not production bundle-size measurements.
2. **Restricted runtime:** both bundles evaluated in a Node VM with `process` and `Buffer` absent, Web-like globals provided, and completed a fake-model input through the Harness (`status: done`). The host `structuredClone` produced foreign-realm arrays rejected by strict JSON validation, so the test used a same-realm JSON clone for these pure-JSON values. This is an import/execution smoke test, not Safari testing or a substitute for real `structuredClone` validation on-device. No live provider request ran.
3. **Edited approval across reopen:** a small custom replay-safe `review_note` tool persisted a pending task document in SQLite. Before close: pending original body, zero effects. Reopening retained both. Updating the body to `edited by human` and approving through a Pi commit resumed the same submission to `done`; the effect executed once using edited text. This used Node SQLite, a fake provider, and graceful harness close/reopen. It did not simulate process kill during publication or prove exactly-once recovery.
4. **Actual Chromium execution:** bundled the same published core to an IIFE and loaded it into isolated headless Chromium 145 using Playwright. With real browser `structuredClone`, `Promise.withResolvers`, Web Crypto, and neither `process` nor `Buffer`, a Harness fake-model conversation completed (`status: done`) and produced `pi.user`/`pi.assistant` entries. No clone replacement was needed. This strengthens browser-core viability; it still does not prove Safari/WKWebView, native storage, or a live provider bridge.

Experiment scripts: `entry.mjs`, `provider-entry.mjs`, `check.mjs`, `vm-check.mjs`, `approval-reopen.mjs`, and `chromium-check.mjs` in that temporary directory. npm package lock records exact transitive versions. Chromium used an isolated temporary browser profile and did not access the user's browsing data.

Minimal portable rerun fixtures are preserved in [`pi-probe/`](pi-probe/README.md), including the exact dependency lock. They omit generated bundles, databases, and installed dependencies. Packaging cleanup added unique temporary databases, browser executable selection through `CHROMIUM_EXECUTABLE`, assertions, and cleanup. The packaged install, bundles, Chromium conversation and SQLite approval/reopen were subsequently rerun successfully; the fixture README records the results and limits. The VM-only exploratory script was omitted because the actual Chromium proof is stronger.

## Decision implication

Pi deserves an iOS native-bridge spike rather than a Node-based rejection. It offers a high deletion ceiling for session orchestration and a useful durable proposal substrate, with additional custom approval protocol work and substantial maturity risk. Compare against a framework with a shipping persisted human-interrupt primitive using the same actual-device and crash-after-note-write tests. Do not select it solely because the larger Pi project is popular.

## Follow-up: Pi extensions and reusable functionality

There are **two distinct extension APIs** in this repository. Their relationship matters more than their similar names.

| Extension surface | Host and capabilities | Reuse inside Gneauxghts |
| --- | --- | --- |
| Coding-agent extensions | Default factory receives `ExtensionAPI`; registers tools, commands, lifecycle/context handlers, providers, MCP, terminal renderers and UI. | Existing ecosystem extensions target this API. Headless/RPC use is possible on a Node host, but they do not automatically register in Durable. |
| Durable extensions | `defineExtension({ name, tools, sections, hooks, wraps, tasks })`, explicitly installed in a registry. | This is the portable API to use for bundled app functionality; its tools/documents/tasks participate in Durable's persisted scheduler. |

Coding-agent extensions are executable TS/JS modules loaded with `jiti`; the stock loader statically imports Node filesystem, module, path, URL, configuration discovery, execution, and MCP infrastructure. Reusing that loader inside WKWebView is not the browser-core route verified above. Its UI abstraction supports ordinary dialogs in RPC as well as TUI mode, but custom components, footer/header widgets, editor factories, and raw input explicitly depend on terminal interfaces. A custom embedded UI does not receive those controls automatically. [Coding extension guide](https://github.com/earendil-works/pi/blob/4954d760504c11df9b2cbdc040346107b6a8153d/packages/coding-agent/docs/extensions.md), [Node loader](https://github.com/earendil-works/pi/blob/4954d760504c11df9b2cbdc040346107b6a8153d/packages/coding-agent/src/core/extensions/loader.ts), [UI/context types](https://github.com/earendil-works/pi/blob/4954d760504c11df9b2cbdc040346107b6a8153d/packages/coding-agent/src/core/extensions/types.ts).

Durable's `defineExtension`, `defineTool`, and hook helpers are simple typed definitions with no dynamic Node loading. The inspected coding-agent extension tree has no import of `pi-durable`, and no stock conversion adapter between the two APIs was found. `pi-agent-core` recently removed its experimental harness in favor of the new package; importing the mature coding-agent extension host is therefore not evidence that those plugins share Durable's persistence/replay semantics. [Durable definition helpers](https://github.com/earendil-works/pi/blob/4954d760504c11df9b2cbdc040346107b6a8153d/packages/durable/src/harness/define.ts), [core split changelog](https://github.com/earendil-works/pi/blob/4954d760504c11df9b2cbdc040346107b6a8153d/packages/agent/CHANGELOG.md).

Concrete composition: bundle a `gneauxghts-notes` Durable extension containing native search/read tool wrappers, evidence prompt sections, freshness hooks, proposal documents, and review tasks; expose committed state to Svelte. Existing coding-agent plugin business logic can sometimes be extracted behind a small adapter, but `pi.on("tool_call")`, `ctx.ui.confirm`, `pi.appendEntry`, tool result `content/structuredContent`, and session-manager calls need deliberate mapping to Durable hooks, app UI, commits, and `output/structuredOutput`. A confirmation dialog alone does not establish a persisted approval decision or a recoverable note commit. Reusing a pure algorithm or provider integration is easier than importing a whole plugin host.

This leaves a valuable reuse path: use Durable's extension system as the location for Gneauxghts-specific capabilities while relying on its session/task kernel. It does **not** mean that the established coding-agent extension ecosystem is currently a drop-in iOS library. Each proposed third-party extension needs dependency, license, API, and replay-policy inspection. Installed executable plugins are trusted code; bundled, reviewed capabilities are the first integration target.
