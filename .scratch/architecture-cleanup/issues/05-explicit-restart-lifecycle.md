# 05 — Own restart preparation before requesting process relaunch

Status: resolved
Depends on: 04; fresh triage required
Scope: deferred; excluded from Round 1. Do not implement without a new scope decision after the Round 1 audit.

Read [the spec](../spec.md) and its execution/measurement rules first. Source lines refer to the 2026-09-07 working tree; use named symbols after preceding tickets move them.

## Problem and evidence

Settings directly calls plugin `relaunch` (`src/lib/features/settings/store.svelte.ts:236`). The current exit callback (`src-tauri/src/lib.rs:361`) clean-closes only timeline and shuts down semantic state, with an external `is_cleanly_closed` check. It does not join all producers. Installed Tauri 2.11.2 ignores `prevent_exit` for the restart exit code; evidence and local dependency paths are in the vault investigation. Issuing relaunch before settlement cannot be made safe by that veto.

## Implementation instructions

1. Add one concrete app-lifecycle restart action. Join the existing pending restore/save barrier before requesting backend preparation; block new workspace mutations during departure. Reuse existing pending-work registration rather than another workspace save queue.
2. Backend `prepare_restart` joins concurrent callers and owns one idempotent close operation. Stop new chat/tool/watcher/projection production, cancel and settle active chat through existing ChatService semantics, release permission waits, and stop watcher/debounce/reconciliation production.
3. Separate reversible producer quiescence from terminal resource shutdown. Keep required catalog/task/history settlement sinks available until timeline recovery/finalization succeeds. Join durable task/metadata transactions and admitted writes; cancel/discard rebuildable work safely without requiring full index catch-up. Add stop/join privately in existing owners, not a generic worker-registration framework. Chat cancellation currently only signals tokens (`chat.rs:2601`); detached title generation continues after request removal (`:2214`–`:2228`). Its title/projection work must also be tracked, cancelled and joined. An empty interactive request map is not a settlement receipt. `SemanticState.shutdown` (`semantic/mod.rs:778`) only stops its provider; explicitly settle indexer/maintenance admission and running work too.
4. Invoke bound `NoteTimeline.clean_close`, preserving lease drain, recovery, finalization, checkpoint, and app-local close watermark. Make repeated close calls join/return the established outcome inside the owner; remove caller `is_cleanly_closed` sequencing.
5. Frontend calls relaunch only after an explicit ready receipt. State is idle, preparing, ready-to-restart (resources closed), or failure with closure outcome. If relaunch fails, remain closed and show Retry Restart; never re-enable editing against closed history.
6. Failure restores editing only if every required owner is usable, not merely when `timeline.closed` is false. Retain whether the app is reversibly quiesced or irreversibly shut down; later failure must offer settlement/restart retry without silently reopening. Every error after entering closing must settle lifecycle state, including `allow_close_settlement_verification` failure before current cleanup (`services/note_timeline/runtime.rs:268`). Ordinary exit uses the same backend operation as fallback; it must not deadlock the event loop while waiting for operations that need that loop. This backend fallback settles admitted work only: it cannot save unsent frontend drafts. Preserve existing ordinary-quit semantics and explicitly report that scope; broader native-quit interception is outside this restart ticket.

## Acceptance and validation

- Repeated Restart joins one operation. No relaunch occurs on save/conflict/restore, cancellation settlement, or close failure.
- Test active run with pending permission, watcher debounce, admitted task write, pending Editing Window, close retry, and relaunch failure after successful close. Preserve durable interrupted-chat output.
- Use deterministic barriers/fake relaunch for unit/integration coverage; no sleep-based race tests. Add a scoped isolated-vault native restart check for real process ordering during implementation.
- Tests distinguish timeline portability from producer completion. Add one justified lifecycle owner while deleting the distributed Apply/Exit/restart protocol; do not claim raw owner count must fall.
- Keep historical scale/native acceptance paused; these are new lifecycle-specific checks, not permission to reopen that effort or touch user vaults.
