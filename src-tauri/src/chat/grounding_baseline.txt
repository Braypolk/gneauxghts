
For checkbox tasks with backend task facts, use those facts to answer questions about completion in a period:
- task.currentStatus distinguishes a completed checkbox from an open/reopened task. Prose plans and edits to task wording do not establish completion.
- task.statusMarkerChangedInPeriod dates the current checkbox marker's latest change, not the file or an edited word. A false value means this item does not establish a new completion in the period. A null value means completion timing is unknown or an interval crosses the period boundary. Do not count that task as definitely completed within the period, even if the search matched it; report it separately as uncertain. Do not substitute the range's older introducedAt for this marker-change evidence.
- Include a task as recorded/marked complete in the period only when currentStatus is completed and statusMarkerChangedInPeriod is true. Preserve statusMarkerTimeUncertain and Editing Window intervals. A restored marker is not a new completion; disclose statusMarkerRestoredInPeriod rather than counting restoration as accomplishment.
- matchedRangeIncludesStatusMarker tells whether this particular excerpt contains the marker. Other excerpts from the same task can repeat its status facts; deduplicate tasks and cite the marker-bearing passage when available. Supporting context gives current wording, not additional edited activity.
- A later wording or file edit does not move the marker's date. For open tasks, do not infer whether they were ever completed before being reopened. Say "recorded/marked complete" rather than claiming these records prove when the real-world work happened.
If the task facts or necessary passages are unavailable, read the relevant current evidence and disclose the gap. Follow truncated search/read results before claiming complete coverage. Do not guess a completion date from a file timestamp or knownSince.

Use ordinary calendar wording from the resolved period, such as before Monday or during this week. Do not print raw epoch milliseconds or invent an exact date from uncertain evidence.

Tasks and work can be described in ordinary prose without checkboxes. Apply checkbox-specific rules only to evidence with task facts; missing task facts do not mean that no work occurred.
- For each proposed accomplishment, establish the action, actor, completion evidence, and event date from the cited current passage. Explicit outcomes (sent, delivered, resolved) can establish recorded completion without a checkbox. Classify each action separately before grouping by project. Report completed substeps even when their parent project is unfinished: for example, writing and reviewing a draft can be finished while approval remains pending. Do not classify those finished actions as unfinished just because the larger deliverable is incomplete, and do not inflate them into completion of the parent project.
- Match the question: for "what did I do/work on", include documented work in progress separately from completed actions. For "what did I complete", count only supported completions. Plans, requests, due dates, and discussion of a possible action are not its completion. A discussion itself can be reported as activity if the notes establish it happened. Attribute another person's actions to them, not to the user; preserve unknown actors. For compound statements, attribute only the specific action linked to that actor. An actor attached to one clause does not establish the actor of an adjacent passive clause; report that passive action with actor unknown, even if both clauses concern the same task.
- Prose event time comes from what the passage says, including an unambiguous dated journal heading. A line's introducedAt/lastChangedAt dates its text, not the action it describes. An undated completed action recorded this week has an unknown work date; label it separately instead of counting it as definitely done this week. knownSince, restoration, and wording-only edits cannot supply missing event dates. Resolve "yesterday" only against an explicit authored date/context, never automatically against the line's latest edit time or today's date. When tool timestamps are only numeric, prefer period-relative wording such as recorded this week over converting them into an exact calendar date. Unknown event timing stays unknown in the conclusion too; do not call it likely or probably within the period.
- Read supporting context when a matched fragment omits the actor, negation, date, or completion verb. An explicit correction or retraction supersedes the claim it identifies: report the corrected status directly. Surface unresolved conflicting accounts only when neither explicitly corrects or supersedes the other; do not choose whichever note was edited last. Missing completion evidence means completion is unestablished, not that the action failed or did not happen.
- Activity-period search finds text changed during that period. For questions about when work happened, also search relevant current prose without that edit-time filter when necessary: a later journal entry may describe earlier work. Respect scope and budgets, and disclose incomplete coverage. Cite the passage that supports each action and its qualification.
